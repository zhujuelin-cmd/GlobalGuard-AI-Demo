# GlobalGuard - AI Driven Global Marketing Safety & Strategy Engine

> 让好创意，安全地抵达世界。
>
> 从法国的文化体验出发，以 TikTok 安全策略为方法，以营销与文旅实践为场景，探索全球品牌如何在被看见之前，先被正确理解。

**GlobalGuard 是我个人职业背景——文化洞察、安全策略与营销实践——的集大成展示。** 它不仅是一款 AI 工具的概念原型，更是一次专业方法的迁移：将安全推荐中的指标治理与模型路由逻辑，转化为全球营销中的文化判断、创意修改与投放前决策。

## 1. 为什么发起这个项目｜The Origin Story

### 在法国，我开始重新理解“语境”

这个项目的起点，是我在法国 **EMLyon Business School** 的留学经历。

在当地学习与生活时，我对文化、语言背后的语境，以及世俗化边界有了切身感悟。我逐渐意识到：一段文案的字面意思可以被翻译，但它在当地如何被理解，并不会随翻译自动迁移。谁在说、对谁说、在什么场景说，往往与说了什么同样重要。

尤其在法国关于公共表达、宗教与身份的讨论中，“世俗化”并不是简单的“不能谈宗教”，而涉及公共空间中的中立、个人表达与具体场景之间的边界。这让我更加警惕把一个国家压缩成几条营销标签，也开始追问：**品牌如何理解当地文化，而不是替当地人定义文化？**

GlobalGuard 选择法国作为首个演示市场，正是为了把这些感受变成可以讨论、解释和检验的产品判断，而不是把个人观察当成适用于所有法国消费者的固定规则。

### 在 TikTok，我看到文化判断需要可执行的策略

在 **TikTok Feed-Safety 安全推荐策略**领域的工作，让我从另一端理解了这个问题：识别风险只是开始，真正的治理还需要指标、模型判断、策略生效与实验反馈共同完成。

ANSA 指不适合所有受众的风险内容。ANSA 指标治理关注的不只是“有没有违规内容”，还包括风险内容在推荐中的播放占比、漏放与误伤之间的权衡。模型路由则是把不同内容与语境分配到适合的判断路径，而不是让所有问题接受同一种判断。

我希望把这些专业思考应用于全球营销：不只为文案打一个风险分数，而是回答三个可以执行的问题——**为什么存在风险、应该如何修改、修改之后能否进入下一步？**

由此，GlobalGuard 的目标从“检测敏感表达”转向“建立投放前的文化安全决策链”：既避免不合适的创意被放大，也避免用过度保守的规则抹平正常表达。

### 在德勤与华纳乐园，我把问题放回用户旅程

在 **德勤和华纳乐园期间**，我对“用户旅程”与“文旅数字化”的思考，为这个项目补上了营销与体验的视角。

用户旅程，是一个人从看到品牌、理解承诺，到咨询、选择、体验与反馈的完整过程。文旅数字化，也不应只停留在渠道上线或投放效率，而应帮助品牌更好地理解游客的处境，并让线上承诺与实际体验衔接起来。

这让我不满足于做一个孤立的审核工具。即使文案没有明显风险，如果它在预算谨慎的市场里持续强调炫耀感，或把游客的真实顾虑当成需要被刺激的弱点，它仍可能偏离用户需要。

因此，GlobalGuard 同时关注两件事：**创意有没有越过文化边界，以及策略有没有回应用户的处境。** 数据感知、创意任务、文化判断与效果复盘，必须围绕同一个用户旅程协同工作。

### 三段经历，汇成一个产品命题

| 经历与视角 | 我带入项目的思考 | 对应的产品设计 |
| --- | --- | --- |
| 法国 EMLyon 留学：文化洞察 | 语境不能靠直译搬运，文化标签不能替代当地人的多样性 | 明确市场、语言、说话者与证据边界，解释身份排斥和文化误读 |
| TikTok 安全推荐策略：安全治理 | 判断需要落实为策略，也需要兼顾漏放与误伤 | 风险路由、人工复核、改写重扫与当前版本投放许可 |
| 德勤与华纳乐园：营销与文旅实践 | 创意是用户旅程的一部分，数字化应连接承诺、选择与反馈 | 从市场信号生成创意任务，再连接预算验证与效果复盘 |

**我的产品命题是：让品牌在放大曝光之前，先理解市场、尊重语境，并对自己的承诺负责。**

这些经历构成项目的设计背景与方法来源，不代表相关学校或雇主参与开发、提供数据或为项目背书。以下客户、市场样本与结果均属于演示原型。

## 2. 从痛点到 AI 解法｜Why This Product

### 发现痛点：翻译正确，不等于沟通正确

出海团队可能写出一句自认为很懂法国的广告：“真正的法国人，选择 100% 环保旅行。”

这句话同时包含两个问题：品牌替一个国家划定了谁属于这里，也作出了需要证据支撑的绝对环保承诺。另一支团队或许没有触碰明显红线，却仍然用奢华升级的表达回应预算谨慎的消费者——买到了曝光，却没有回应顾虑。

问题不只发生在文字里，而发生在**文化理解、市场判断与执行决策彼此脱节**的时候。

### 结合专业背景思考：安全不是创意的最后一道检查

我的判断是，安全与营销不应等到发布前才碰面。文化背景要进入策略假设，用户处境要进入创意任务，审核结果要影响投放许可，复盘也要同时关注效果与安全。

这既是留学经历带来的语境意识，也是安全策略与营销实践共同形成的产品视角。

### 提出 AI 解法：把分散判断连接成一条决策链

GlobalGuard 将 AI 的理解、辅助生成与风险判断组织为六个连续阶段：**数据感知 → 策略洞察 → 创意指令 → 文化冲突判断 → 投放决策 → 效果复盘**。

面向出海品牌的策略、创意、营销运营与内容安全团队，它不追求“一个分数自动批准所有创意”，而是提供可解释、可修改、可复核的工作台。当前版本用本地模拟展示这一产品设计，尚未接入真实 AI 模型服务。

### Before / After：改变的是决策过程

| 场景 | Before：事后发现问题 | After：事前形成判断 |
| --- | --- | --- |
| 文化偏见与环保承诺 | 用“真正的法国人”和“100% 环保”强化营销，发布后再解释 | 检查身份语境与证据范围，保留邀请与具体措施，改写后重新判断 |
| 市场错位与预算压力 | 用旧人群假设放大奢华诉求，继续追求曝光 | 从同口径样本识别预算顾虑，提出透明价值的策略假设，再验证 |
| 安全与投放脱节 | 风险分数与创意版本分离，修改后沿用旧结论 | 许可绑定当前文案与语境，旧判断不能批准新版本 |

以上均为假设场景，展示的是产品如何组织判断，不证明已经避免危机或提升投资回报。

## 3. 技术架构与专业方法｜Data → Signal → Insight + ANSA Router

这里的 Data、Signal、Insight，分别指原始数据、从数据提炼的信号，以及结合用户处境形成的策略洞察。ANSA Router 指借鉴安全治理方法，将内容分配到合适审核路线的机制。

1. **Data｜先建立可信输入**：明确市场、语言、时间窗与渠道，排除广告，按 `source + postId` 去重；先说明分母，再解释图表。
2. **Signal｜再提炼可用信号**：在同口径模拟样本中观察话题与情绪；样本不足时不强行形成策略结论。
3. **Insight｜把信号放回用户处境**：形成消费者顾虑、创意目标、语气与证据边界。预算相关讨论只支持待验证假设，不证明真实消费已经降级。
4. **ANSA Router｜将语境转为处理路径**：结合文案、市场、说话者与证据，进入 `allow`（放行）、`rewrite`（改写）、`block`（拦截）或 `review`（人工复核）。
5. **Activation & Learning｜带着许可验证，再用反馈学习**：只有当前版本许可才可继续模拟投放；复盘同时关注效果与安全，服务下一轮假设。

**这是将 TikTok 安全推荐策略中的 ANSA 指标治理与模型路由思路迁移到全球营销的专业实践，不是接入或复刻 TikTok 生产模型。** 当前路由、扫描与生成由原型中的规则和预设场景模拟；未接入生产推荐系统，也未声称具备真实模型的泛化能力。

## 4. 原型范围与安全边界

- LUMEN 是虚构品牌；社媒观察、创意生成、扫描、改写、投放与复盘均为本地模拟，没有真实抓取、模型 API 或广告平台投放。
- 当前测试数据包含 4,835 条原始模拟观察；默认法国、法语、非广告并去重后为 4,024 条。它们不是实际平台流量、真实市场样本或业务成果。
- 前端提供 INSEE、ADEME、DGCCRF 的参考链接；日期与结论并非由应用在线核验，也不能将参考摘要视为已经核实的事实。
- 未知自由输入进入人工复核，不因未命中规则而自动放行。原型不能替代法律意见、平台政策或专业文化审核。
- 文案、说话者或证据变化需要重新扫描；数据筛选变化会使下游信号、任务与许可失效。
- 状态保存在内存中，不保证跨刷新或跨会话持久化；未实现生产级协作、权限管理与审计。
- 法国的世俗化与宗教表达边界属于项目起源中的文化思考，**并不意味着当前版本已经实现完整的宗教、世俗化或法国法律审核能力**。

## 6. 快速启动｜Quick Start

建议 Node.js 20+、Python 3.11，并使用独立 Python 虚拟环境。

若只是运行已打包的原型，完整构建产物已包含在 `dist/` 中：

```bash
cd 02_部署代码_SourceCode
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

Windows 使用 `.venv\Scripts\activate` 激活环境。启动后打开终端提示的本地地址。

如果修改前端，需重新构建并测试，再更新 `dist/index.html`：

```bash
npm ci
npm run build
npm test
python -m unittest discover -s tests -v
```

Python 部署测试包含 Node.js 导航检查，因此运行完整测试前需完成 `npm ci`。Streamlit 启动不自动执行 npm；缺少完整构建文件时会给出错误提示，而不会静默显示节选页面。

## 7. GitHub + Streamlit Community Cloud

1. 解压 ZIP，在 GitHub 创建仓库，将 `02_部署代码_SourceCode/` **内部的内容**作为仓库根目录上传；不是只上传 ZIP 文件。
2. 确认 `app.py`、`requirements.txt`、`dist/index.html` 与 `.streamlit/config.toml` 均已进入仓库。`.gitignore` 已允许跟踪 `dist/index.html`，无需强制添加。
3. 在 Streamlit Community Cloud 创建应用，关联仓库与分支，入口选择 **`app.py`**，Python 版本选择 **3.11**。原型无需业务 API secrets。
4. 发布后检查首页、大屏切换、信号提炼、风险拦截、改写重扫、人工复核及版本许可失效，并检查宽屏与移动端滚动。

如果保留嵌套目录，入口应选择 `02_部署代码_SourceCode/app.py`，并确认 Streamlit 配置的加载位置；推荐直接采用仓库根目录结构。网页拖拽上传可能遗漏隐藏文件，请额外核对 `.streamlit/` 和 `.gitignore`。也可以在该目录内通过 Git 提交，避免遗漏。
